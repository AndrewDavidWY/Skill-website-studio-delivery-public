# 网站策划与交付

把定位、内容、信息架构、视觉、开发、内容管理、验收与交接连成一套可维护的网站交付方法。适用于个人、企业和组织的公开网站。

**这是建站方法 Skill，不是官网程序、可直接运行的网站模板或生产部署脚本。网站源码应放在各自项目仓库，与本 Skill 分开维护。**

技能名称：`website-studio-delivery` · [查看技能指令](SKILL.md)

## 适合什么时候用

- 从资料出发规划一个个人或企业官网。
- 优化现有网站的栏目、阅读、导航与移动端体验。
- 维护多语言、内容管理、图书或媒体等内容模块。
- 按授权完成 GitHub 协作、OSS 发布或证书流程，并留下验证记录。

## 开始前准备什么

- 网站目标、受众、页面范围及当前要完成的阶段。
- 现有仓库、页面、品牌素材和可核验的内容。
- 语言、设备、技术栈、托管与发布要求。

## 工作方式

1. 先确认项目、范围和现有修改，再组织内容与访客路径。
2. 沿用可用工程及视觉约定，把方案落到真实页面。
3. 按需处理 CMS、多语言、媒体及相关专题。
4. 分别核对源码、构建、浏览器、上传和线上结果。
5. 交付维护入口、发布记录及实际验证边界。

## 可以得到什么

- 网站策划、信息架构、页面方案或授权范围内的实现。
- 内容覆盖、编辑验收和交付记录。
- 按需准备的发布、回滚与维护说明。

## 安装与调用

本仓库是网站策划与交付 Skill 的公开交付快照，只包含可公开的技能方法和空白模板，不包含网站源码、客户资料或旧仓库 Git 历史。

将完整仓库克隆到自己的技能目录，安装文件夹使用技能名称 `website-studio-delivery`：

```sh
git clone https://github.com/AndrewDavidWY/Skill-website-studio-delivery-public.git ~/.codex/skills/website-studio-delivery
```

如果使用自定义 `CODEX_HOME`，请放到其 `skills/` 下。同名目录已经存在时先比较版本并保留自己的修改，不要直接覆盖。下载 ZIP 时，同样需保留完整文件结构，并把解压后的安装目录命名为技能名称。

在新会话中确认技能可用，再用下面的方式提出任务：

```text
使用 $website-studio-delivery，先检查这个官网的内容与页面结构，优化栏目首页和手机体验。保留现有框架与素材，完成本地预览和检查，本轮不上传。
```

Skill 不附带账号、凭据、网站源码或已部署任务。GitHub、OSS、DNS、SSL 与第三方工具权限仍需按项目确认。SSL 续期和云端发布部分是实施指引，不代表已经配置或正在自动运行。
