# 网站定位、结构与视觉

## 输入与事实边界

先建立简短资料清单，记下名称、版本、用途与冲突。常见输入为 SVG、品牌色与 VI、企业简介、PPT/PDF、照片视频、参考站和用户补充。读取 PDF/PPT 时兼顾正文与页面视觉；环境提供相应文档技能时使用它们。

优先处理影响整站的冲突，例如个人/机构主体名称、指定 LOGO、核心定位、主要业务和真实联络入口。其余内容缺口不阻塞独立的设计工作。把信息分类为：

| 类别 | 处理 |
|---|---|
| 已确认事实 | 用作公开文案，并留来源 |
| 资料间冲突 | 记录采用依据；关键冲突向用户澄清 |
| 筹划/探索业务 | 明示状态，不写成已实现成果 |
| 待补信息 | 内部清单保留，页面不编造 |
| 示意素材 | 不包装成客户、项目、办公室或合作关系 |

## 把参考站转成自己的表达

读取用户给出的参考站；如视觉访问不可用，说明实际只读取了哪些内容。提取可复用的表达原则，例如主张位置、文字密度、影像比例、导航状态和行动入口。不要声称逐像素复刻；不要复制未经授权的素材或证据性信息。若用户指定参考站的特定交互或视觉细节，应明确复现目标并对照检查，不把“参考”误解成仅取配色。

组织官网可按“理解组织 → 看见能力 → 找到适用服务 → 建立信任 → 行动”组织；个人官网可按“认识本人 → 了解专业领域 → 查看作品/研究 → 建立信任 → 联系或参与”组织。具体模块由访客任务和材料决定：集团服务站可能需要成长路径，制造企业可能更需要产品、产能与采购入口，个人专业站可能更需要研究、作品和预约。

做栏目首页优化时，一起检查主首页、全局导航和相邻栏目，明确全站共用的视觉规则与栏目自己的任务。对已经确立的封面和主首页做视觉延续，但不要机械复用相同 Hero、卡片排列或模块次序。把页面差异落实到实际信息和访客路径。

每个模块先写一句目的、核心内容和可执行入口，再做视觉。为页面明确主要行动优先级，例如咨询、产品询价或阅读研究；不同栏目可有不同任务，不把全站限制为一种转化行为。

## 栏目与内容规划

先列受众、访客任务、内容支柱、类型和导航关系，再把内容映射到栏目首页、分类/列表和详情模板。重复内容使用稳定模板，完整正文、来源、媒体和相关入口分别验收；卡片摘要不能代表全文交付。使用[内容覆盖表](../assets/content-coverage.md)记录范围与缺口，搜索、筛选、CMS 按需读[内容结构与 CMS](content-cms.md)。

重要陈述注明来源版本、时效、审核责任和可公开范围，区分事实、假设与宣传表达；通用技术资料不能证明特定机构或项目已实施该能力。缺失资料在内部留待办，不能用虚构数据补齐页面。

## 视觉实现

- 建立颜色、字号、版心、间距、按钮和边界状态；检查小字与按钮的对比度。
- 原 SVG 保持比例与视觉形态；明确要求原文件时逐字节核对。不要因为另一本 VI 出现新 LOGO 就自行替换。
- 视频先保证静态封面与正文可读，再做按需加载、静音播放、暂停、失败反馈和减少动态偏好。
- 移动端按阅读顺序重新组织，不只是整体缩小。关键内容不能只能悬停查看。
- 单文件 HTML 适合离线审阅；线上素材宜拆分，以便缓存和维护。不要用大体积内嵌演示稿直接替代最终构建。

需要人物肖像素材且用户选择董事长官网风格时，按需使用[中英肖像提示词](portrait-prompts.md)。先确认本人参考照片的使用权与页面构图需求；生成后核对身份辨识度，创作肖像不能充当真实事件证据。

## UI/UE 复核

逐项对照实际动作：按钮是否到正确目的地，卡片是否显示所选内容，导航是否遮挡标题，菜单是否能关闭，弹窗焦点是否返回，键盘和触摸是否可用，视频是否互相抢播。下拉菜单要实测鼠标从触发项移入子菜单的连续路径、慢速移动、滚动后导航状态和触屏打开/关闭，不只检查静态外观。

CTA 写明行为，避免“开启合作”却只显示占位说明。缺少后台时可做清楚标注的演示或真实邮件/电话入口；不能出现虚假“提交成功”。

改版说明采用“问题 → 调整 → 对访客的改善 → 验证方式”，保留必要的前后版本，不追求无依据的性能数字。

## 内容体系与持续编辑

- 先建立内容类别、栏目首页、详情页和关联入口。专题、研究项目、论文、观点、工具等可关联，但不要为了统一版式而混成一种内容。
- 人物、谱系与文化站区分公开可核实资料、族谱自述、传说和待考；同姓不自动构成同宗，不把搜索摘要当事实来源。
- 标准分类保持官方版本、代码和父子关系；不同分类维度分开导航。已有资料只归到证据支持的层级，不能自动补更细分类。空分类也可浏览，数量大时采用搜索、路径导航和分页。
- 按真实内容选择列表、长卷、图谱等表达；目录层级和手机阅读顺序优先于视觉复杂度。

## 精修指定版本与滚动动效

以用户指定文件/版本为基线，保留可回看原件；内容、布局和交互分别说明改动。新方向可作为候选，不覆盖已选版本。头像和人物图片逐张检查焦点与裁切，避免切掉面部或改变指定素材方向。

滚动文字优先随页面实际位置变化，保留原生滚轮、触摸和键盘滚动。避免劫持滚轮制造翻屏；确有特殊叙事需求时再评估。逐字拆分保留标题语义和完整可读名称，避免读屏逐字重复；中文断行与英文单词换行分别处理。支持系统减少动态效果；页面提供关闭动效入口时保持偏好一致。

JS 未执行或高级 CSS 不支持时正文仍应可读，不能把初始透明状态变成空白首页。离线预览与线上构建应来自同一份内容和样式，检查语言切换、锚点和资源路径，避免维护两套逐渐分叉的版本。
