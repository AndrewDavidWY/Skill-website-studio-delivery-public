# 工程化与验收

## 项目结构

如果已有可用工程，沿用其约定。新建 Astro 展示站可采用：

```text
project/
  src/pages/             首页、404、其他路由
  src/components/        业务模块
  src/layouts/           页面框架与 metadata
  src/styles/            公共样式
  public/assets/         准备公开的素材
  scripts/               构建检查、发布与证书辅助工具
  docs/                  策划、素材来源和维护说明
  reports/               验证与发布记录（不放秘密或公开备份）
  certificates/          仅私有本地使用并排除版本控制；优先用户私有配置目录
  dist/                  实际构建输出（以项目配置为准）
```

源码、内部文档和公开目录分开。需要表单收件、会员、支付或 CMS 时单列后端交付；静态页面不会自动实现这些能力。

Astro 静态站可构建后部署输出目录；需要按需渲染时需匹配运行环境。核查当前支持版本与 Node 要求，保留锁文件，不把历史版本号写成永远适用的要求。[Astro 部署文档](https://docs.astro.build/en/guides/deploy/)

迁移视觉 HTML 时注意组件脚本处理、CSS 提取、资源路径与 noscript 样式：不要让只应在无 JavaScript 时生效的规则进入正常页面样式。为页面设标题、描述、站点 URL；404 不应被误当作首页 canonical。只有确定正式主域名与跳转策略后才统一 SEO 地址。

## 验证层次

| 层次 | 有用证据 | 不能推出 |
|---|---|---|
| 静态构建 | 构建成功、路由/资源存在、锚点和 ID 正确 | 浏览器显示正确 |
| 模拟交互 | 状态切换、边界、焦点逻辑 | 真实触摸、媒体播放、视觉布局 |
| 浏览器 | 桌面与手机截图、实际点击和键盘检查 | 线上部署成功 |
| 上传 | 清单、对象大小或校验值一致 | 自定义域名可访问 |
| HTTP | 各配置域名首页/资源、404、媒体 Range | HTTPS 证书有效 |
| HTTPS | 无忽略 TLS 错误的访问、域名覆盖、有效期 | 自动续期已启用 |

浏览器检查选择能代表布局变化的宽度，例如 1440、768、390、320，以及短屏/放大文字。数值可按项目调整。检查无横向溢出、按钮易点、导航焦点、弹窗退出、媒体失败回退。无法执行的部分标“未验证”。

发布前扫描输出目录，排除私钥、凭据、配置秘密、备份、内网文档；检查源映射和构建内容是否意外携带私有信息。不要仅依赖 .gitignore，它不控制 OSS 上传。

发布后逐域名以真实 GET 检查已配置的裸域与 www 根 /、带 query 的根（如 /?verify=<版本>）、适用的 /index.html、/about/ 等实际入口；不为未配置域名擅自新增绑定。核对正文与该次构建内容，不能仅依据 manifest 对象成功。HEAD 目录可能 404 而 GET 200，不能用 HEAD 替代 GET。检查 HTTPS、关键资源和本次媒体清单。保存状态、内容比对与浏览器截图证据。

发布后核对实际路由及内容。小站可逐个 GET 并比较 SHA256；大型站选择变更页面及关键资源。简单上传的 ETag 可辅助核对，但不要把分片上传或加密对象的 ETag 一律当 MD5。

## 维护与回滚

交接源码时包含锁文件及构建必要资源，在干净目录中按项目约定安装/构建；不要携带依赖缓存、机器配置或凭据。必要资源取回流程须可用，不以缺文件的成功构建代表完整交付。秘密模式扫描只证明已检查的模式和范围，不等于安全审计；依赖安全发现单列。

记录每次测试对应 revision、环境、浏览器实际 viewport 和限制。resize 调用成功不代表已有手机截图；模拟状态通过不代表触屏/播放通过。local checks、remote CI、PR merge、upload complete、live verified 各有独立状态。仅 main 触发的 workflow 未在 PR 运行时写“PR CI 未运行”。

新增栏目同时回归旧页面；多语言生成器按[多语言参考](multilingual-seo.md)比较全部既有 URL/alternate，并核对 HTML head。CMS 与媒体专项按相应参考及[编辑验收表](../assets/editor-acceptance.md)选择情景，不把文档写“通过”当独立验证。

把一次性命令固化成项目内可读的流程；上线工具需指定目标、先预检、备份被覆盖文件及有关 metadata/设置、记录发布清单。素材可先上传、HTML 最后更新。回滚恢复页面、匹配的资源和必要响应头；只备份源码不构成线上回滚。

独立记录真实联系方式、业务文案确认、版权素材、正式表单、隐私说明等内容缺口。按网站实际用途处理，不机械增加与业务无关的流程。

## 多语言与浏览器适配

- 核对每个语言的完整正文、导航、按钮、弹窗、表单说明、标题、描述与配图。语言入口不能把未翻译内容伪装成完整本地化版本。
- 语言选择与完整翻译状态按[多语言参考](multilingual-seo.md)核对；实际优先级由产品确定，存储不可用时仍可访问。手机语言标签要在真实 viewport 逐语种检查。
- 切换语言核对对应页面、锚点和阅读位置；媒体播放连续性只在实际需求中实现并验证。
- 新增内容检查最新排序、旧链接兼容、sitemap、canonical 与 hreflang；测试应验证真实规则，避免把某篇旧文章固定成永远最新。
- 桌面视口检查不等于 Safari/Firefox/Chrome 兼容测试。分别记录真实浏览器与版本、视口和操作；只检查代码兼容性时明确说明未在该浏览器运行。
- 为 svh、backdrop-filter 等效果保留可读回退。交互重点验证 dialog 焦点与退出、触屏菜单、动态关闭和键盘操作。
- 浏览器工具受限制或管理策略阻止时，报告限制，保留静态/HTTP 验证；不得换入口或工具绕过限制，也不得声称实际截图验收通过。

依赖审计记录公告、影响范围和修复状态；不存在修复版本时不要强制换框架来制造“已修复”。仅当变更、失败或未决风险需要时扩大测试，不反复运行已完成的整站验证。
