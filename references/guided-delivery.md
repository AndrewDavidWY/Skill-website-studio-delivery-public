# 分步配置与交付

用于用户亲自完成控制台配置的阶段；代理能够在现有授权下完成的操作应自行执行，不把全部工作转交用户。

## 一次推进一个可验证步骤

1. 先说明当前已完成和缺少什么。只询问影响下一步的缺项，例如 Bucket 名称与地域。
2. 给出准确的控制台入口、按钮和字段值。两项以上字段适合用“字段 / 填什么”表格；占位符与真实确认值要区分。
3. 说明完成后的简短回执，例如“两项已添加”。回执只是执行线索，不能替代工具验证。
4. 用户回复后检查实际状态，报告可观察结果和下一步。不要重复让用户填写已正确完成的配置。
5. 菜单名称、工具版本、证书申请条件及收费可能变化，实施时查当前官方说明；不要照搬历史截图或价格。

一个回复通常只聚焦一个控制台任务；并行且简单的字段可以一起填写。用户需要完整清单时直接给全流程。缺少权限或工具时明确哪一步需所有者操作，继续不依赖该缺项的工作。

## RAM → Secrets → 预检 → 上传 → 域名 → HTTPS

顺序按现有项目调整，域名绑定也可先准备；每一阶段都有自己的验证结果。

| 阶段 | 用户填写或执行 | 代理准备与验证 |
|---|---|---|
| 发布身份 | 创建专用 RAM 用户、保存 AccessKey、绑定策略 | 根据确认的 Bucket/前缀生成最小权限 JSON；不要求聊天发送密钥 |
| GitHub Secrets | 在 Settings → Secrets and variables → Actions 添加约定字段 | 使用项目实际名称给出 ID/Secret 映射；仅查看是否存在，不读取或输出值 |
| 云端预检 | 必要时补准确缺少的权限 | 检查目标地域、列举/读取；只读成功不能证明 PutObject 权限 |
| 上传 | 已授权发布时开启项目发布开关 | 先检查构建、备份覆盖对象并保存私有备份，再上传资源和 HTML；认证读取校验 |
| 静态网站 | 默认首页、子目录规则 | 多语言目录有独立首页时启用子目录首页；错误页必须实际存在 |
| 域名 | OSS 域名绑定、DNS 网站记录 | 两件事分别核验；CNAME 以控制台目标为准，保留邮件和验证记录 |
| 公开访问 | 专用公开网站桶的匿名读取配置 | 先核实错误正文和目标范围；只授予匿名读取，不授予列举或写入 |
| HTTPS | 申请匹配证书并在实际入口绑定 | 分别验证各已配置域名的 SAN、有效期、TLS 与页面；尚未申请就如实记录 |

可采用 OSS_ACCESS_KEY_ID 和 OSS_ACCESS_KEY_SECRET 作为新项目字段名；已有项目沿用其名称。示例名称不代表 Secrets 已创建。

开关关闭或 workflow job 被跳过时报告“未上传”；明确开启后 main 更新是否触发正式站。只读预检不应因为开关开启而意外带上上传动作；调用前核对 workflow 的实际执行路径。

## 从失败中定位下一步

- HTTP 403：读取 OSS 错误码与正文，区分对象缺失、Bucket ACL、Policy 和阻止公共访问；不要仅凭状态码扩大权限。
- 上传成功但根路径打不开：检查默认首页、子目录和自定义域名绑定；GET /index.html 成功不代表 GET / 成功。
- HTML 被下载：检查自定义域名入口及响应头，不能仅用 Bucket 默认域名判断网站预览。
- HTTPS 域名不匹配：证书未覆盖或未在实际入口绑定；不忽略 TLS 校验来宣布通过。
- Secrets 存在但连接失败：核对用户、目标地域、策略实际绑定及失效状态，不索取主账号密钥。
- 页面已一致：核对版本或文件校验值，避免无意义的重复覆盖。

## 简洁回报

先给已验证结果与入口，再给当前待办。可以写“文件已上传并校验；HTTP 已通过；HTTPS 尚未申请”。不要只写“部署成功”掩盖中间缺项。浏览器检查受限时单列未验证项，不把网络访问检查描述成视觉验收。
