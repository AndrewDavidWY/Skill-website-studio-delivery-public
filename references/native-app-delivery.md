# 官网内容服务原生 App

当官网与 iOS、安卓或其他原生客户端共用公开内容时使用。先确认内容发布来源、客户端版本、已有收藏与阅读进度、离线要求和正式发布目标。记录线上事实与本次设计的边界。

## 统一内容源

- 编辑仍走官网既有流程。目录、正文、发现配置和离线包从同一次正式构建生成。先按发布状态与语言过滤，再校验实际可读路由、锚点和资源。草稿、私有数据及后台凭据不得进入分发产物。
- 内容 ID 跨语言稳定，类型参与命名。章节沿用原有章节 ID，正文实际语言与界面语言分别记录。翻译缺失时明确标注回退语言。正文按条目与章节按需读取，客户端解析结构化块，逐步保留必要的旧正文回退。
- 发现页复用官网已有精选、服务和解决方案配置。原生端从目录用 ID 解析卡片，校验入口归属，沿用上次可用的同语言配置作为回退。
- 整本书与文章合集分别提供包 ID、语言、版本、大小和 SHA-256。改变一包时，其余包的哈希应保持一致。首版可从现有静态托管发布。将视频、需要外部授权的素材及可离线展示的配图分别标明。

## 旧数据与更新

- 先读取旧版的真实存储结构。用已知旧 ID 或规范化路径映射到新 ID，保留歧义和未匹配项。迁移应幂等，保留首次迁移前的记录。升级测试必须使用同一 App ID 和签名覆盖安装。
- 收藏、最近阅读、正文位置与图书章号分别验证。旧进度若基于数组索引，新块顺序变化时保留旧版正文或进行显式映射。按书、章节、语言区分存储键。
- 下载前向用户展示版本和大小。临时接收，检查响应的包 ID、语言、版本、字节数和校验值，再原子替换该包。下载中断、空间不足、校验失败或取消时继续使用上一份可读副本。分包管理下载、更新与删除。
- 上传不可变包后再更新索引。跨对象发布时，新旧客户端可重试并继续使用已验证副本。回滚时先恢复可用的内容文件，再切换索引。

## 验收

| 场景 | 验证证据 |
| --- | --- |
| 来源及发布 | 用准确提交、构建产物、发布范围和线上 GET 对齐内容 ID、语言、资源与校验值 |
| 旧版覆盖升级 | 预先写入旧收藏、最近阅读、滚动位置和书籍章节，再用新版打开同一条目 |
| 发现与服务 | 两端用同一份已发布配置打开对应内容，核对本地回退和语言切换 |
| 整书及合集 | 下载后断网并重新打开 App，逐章或逐篇阅读，检查代表性图片及阅读位置 |
| 独立更新与失败 | 修改一个包并校验其他包版本保持一致，模拟下载中断或错哈希后再打开旧包 |
| 手机和平板 | 检查窄屏与宽屏读书、弹窗、导航、进度和失败提示 |
