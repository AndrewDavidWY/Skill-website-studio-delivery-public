# 官网内容服务原生 App

在官网向 iOS、Android、TV 或桌面客户端提供公开内容时使用。先列出网站、接口、各已安装客户端的版本及支持范围。官网新增能力不会自动成为客户端能力；本文是网站侧交付方法，不是四端全部通过的验收声明。网站负责公开内容源、接口、兼容性与发布；下列客户端检查用于联调验收和向 App 团队交接，不在未委托时实施原生 UI、签名或设备安装。App 策划、交互、缓存实现与安装交付由独立的 APP 策划与交付 Skill 承担。

## 同源内容与兼容契约

- 编辑沿用官网现有流程，从同一经核验的公开内容版本生成目录、正文、发现配置和离线包，沿用项目实际构建与发布流程。按内容发布状态、译文状态与实际路由过滤；草稿、后台资料与凭据不进入公开分发。不要手改构建目录或另建会失去同步的 App 正文库。
- 稳定内容 ID、展示元数据与资源版本分开。标题、译名、封面和排序变化不重建收藏身份。请求/界面语言与真实正文语言分别记录，缺译文时明确回退，不把界面翻译当全文翻译。
- 描述符明确路径、schema、身份、语言及实际提供的长度/hash。正文或章节变化应沿书目录、内容目录传到入口版本。hash 对应 HTTP 解压后的原始文件字节，不是压缩传输体，也不是解析后重新序列化的 JSON；hash 不是可排序版本号或发布日期。
- 保留旧字段语义。新增可选富文本或图片尺寸字段可渐进接入，旧客户端仍能读原正文块。未知类型安全跳过或打开原文；已知格式损坏不能冒充一次成功更新。语义树不是任意 HTML 执行接口，保留可读内容和安全链接，过滤脚本及事件属性。
- 发现页沿用官网精选、服务和方案配置；用同语言目录的 ID 解析卡片，缺失项不随意补成无关内容。导航有自己的身份、版本和回退规则，不以目录更新代替导航验证。

## 缓存、媒体与搜索

先核对各平台真正实现的更新链，分别记录目录、正文、封面、导航、搜索和离线包的刷新来源。目录成功不证明这些资源都已最新。

- 新数据先进入候选区，校验 schema、身份、路径范围、语言和已声明的 bytes/hash。确认请求仍有效，再写入对应缓存并提交可见状态。旧请求、取消及迟到响应不得污染新语言或新修订的数据；合并请求还需处理最后一个等待者退出。
- 在线失败时保留上次验证通过的同语言版本，首次使用再按实际能力回退到随包快照。没有描述符的旧响应可以走兼容路径，但不能标记为通过新完整性校验。
- 封面区分明确封面、当前正文首图、确认无图与网络失败。首图结果绑定正文 revision，错误不缓存成永久“无图”。图片变体按显示尺寸、像素密度、格式支持和字节量选择；原图与降采样图分开。
- 在线原图或预览的 hash 不一定适用于离线重编码图片。分别定义哪些字节由哪个描述符或包 hash 验证；离线图片映射属于整个包时，不能误用在线图片指纹否定合法转换。
- 搜索注明检索范围与版本：标题目录、随包全文、在线分片和已下载离线内容不是同一能力。按条目 revision 检查全文覆盖，明确未索引和离线不可搜索项；网站有搜索接口不证明客户端已接入。

## 旧数据与离线更新

- 读取旧版真实存储结构，用已知旧 ID 或规范路径映射。迁移幂等，保留歧义和未匹配项及迁移前记录。覆盖升级使用相同 App ID 与正确签名，不以卸载重装替代保数据测试。
- 收藏、最近阅读、正文位置、书籍章节和偏好分别核对。顺序块号只属于当前修订，不是跨修订或译文的稳定锚点。可保留旧正文继续阅读，或设计显式位置迁移与可见回退；不因语言切换清空当前内容，也不无视用户明确要求切换当前正文。
- 整书与文章合集独立提供 ID、语言、revision、大小及校验信息。下载前显示真实大小；单包上限与总缓存预算分开，沿用项目实际值，不把某次 32 MiB 或 200 MB 变成通用规定。
- 临时下载、完整校验，再原子切换该包；中断、取消、空间不足和坏 hash 时仍有旧版可读。审查实际文件替换顺序，先删旧目录再 rename 并不具备完整失败回滚。更新一包应保持其他未变包的身份与字节版本。
- 明确包内正文/图片与仍需联网的视频、音频、地图、第三方素材；不得将可点击链接描述为媒体已离线。真正断开全部网络并重启 App，再打开已下载正文、代表性图片与章节。

## 发布窗口与区域边界

优先发布不可变资源并验证，再切换索引入口。只有上传实现和验收证明此顺序，才称为已具备；“资源先于 HTML”不等于 manifest 晚于正文，各 JSON 同批并发上传也不构成事务。

固定地址可能出现新旧字节混合。按项目定义有限重试，例如重新取得入口及目录后重试一次；仍不一致则保留已验证缓存，不无限刷新、不覆盖可读旧版。回滚需要匹配资源和索引，而不只是回退网页。

核对每个域名和地区实际承载内容。独立封面、统计数据节点与完整 Reader 服务不是同一范围；不能把某个看板的地区路由推广为全站双活，也不自动修改 DNS、签名、权限或发布渠道。

## 验收与交接

使用[原生内容适配验收表](../assets/native-app-acceptance.md)，记录实际版本和每平台状态：

- 检查所有公开目录项的正文或章节覆盖、身份、语言、描述符和资源字节；不只检查每类第一篇。
- 覆盖新旧 schema、缺译文、未知类型、错误 hash、取消/迟到响应、切换语言、断网重启和旧版覆盖升级。
- UI 按输入方式验证：手机触控/返回、宽屏分栏、TV 遥控焦点与退出、桌面键盘/鼠标和 WebView 历史。纯逻辑测试不证明手势、音频、耗电或真机表现。
- 网站构建、线上接口、客户端下载/解析、安装、启动与真实操作分别列通过、失败、未运行或阻塞。统计 HTTP 204 只证明请求响应，不能证明分析后台入库。

## 经验来源与已知边界

本次方法来自 W.Y. Reader 与 yutengfei.com 的接口、缓存及多端修复核对。公开可检查入口包括[正式 manifest](https://yutengfei.com/reader/v1/manifest.json)和[图书目录示例](https://yutengfei.com/reader/v1/zh/books/blockchain.json)；访问时须重新确认当前版本，不把历史观察当永久事实。

核对发现：网站已有原始字节版本链和博客可选 richText；本次核对的 iOS 0.6.10 / Build 56 仍使用旧 blocks，全文索引有随包来源；网站固定地址 JSON 并发上传存在版本窗口；Android 一处目录替换先删除旧目录。这些限制支持上面的兼容、有限重试和替换验收规则，不表示本次修改了 App 或修复了线上发布机制。跨修订精确读位、四端富文本接入与全部真机验收仍需各项目单独证明。
