# GitHub 协作与云端 OSS 发布

仅在用户选择 GitHub 协作或持续部署时使用。先确认实际仓库、默认分支、站点与发布目标；以下是通用流程，不预授任何外部操作权限。配置时核查 GitHub Actions、仓库套餐与 OSS 当前官方说明。

## 协作身份与分支

- 其他参与者使用各自 GitHub 身份接受协作邀请，并连接支持代码读写的 bot/Codex。分享仓库链接不等于可读写；用户名或 GitHub 已连接也不能证明全部所需权限。核对实际连接账号、仓库访问与工具能力，不共享账号、Token 或 OSS 凭据。
- 每项任务独立分支，先同步最新 main（或实际默认分支）；保护已有改动，合并冲突按双方意图解决，不能覆盖他人工作。PR 写明问题、改动、测试和已知缺口。未获合并或发布授权，不直接写 main，也不执行会触发正式发布的合并。
- 个人私有仓库 collaborator 通常具有写权限；文字约定不能技术强制只走 PR。检查实际分支保护、必需检查、环境审批及套餐支持，不声称未启用的保护存在。仓库写作者可能修改 workflow，普通 repository Secrets 不是对写作者的强隔离；评估受保护环境、发布身份与审阅边界后再配置。
- 不自行邀请人员、扩大权限或迁移账号。与外部 bot 直接交流须有明确对象及动作授权；允许 GitHub 协作不自动允许给他人发消息。

## 迁入仓库与发布准备

检查将提交的源码、素材与旧 Git 历史，排除 .env、私钥、证书私密状态、凭据、依赖目录和缓存。扫描结果不输出秘密值；历史发现秘密时停止传播，报告位置与所需处置，不擅自重写远程历史。大媒体明确选择 Git/LFS/授权素材存储及构建取回方式，核实额度与云端可读性，不偷偷漏掉文件。锁文件和构建所需公开素材应齐全。

分别记录 GitHub 读写身份、构建执行环境与 OSS 发布身份。持续部署凭据由用户本人经安全入口输入；不要求在聊天粘贴，不写仓库或输出日志。RAM 身份只允许目标 bucket/前缀所需读写与备份操作，不附带账号管理或任意桶权限。缺少必要权限时报告具体缺项，不自行扩权。

## 云端流水线与授权

沿用项目包管理器和锁文件进行确定性安装；Astro 静态站构建 dist（以配置为准），执行项目静态检查、路由/资源检查以及部署保护测试。验证未授权分支、PR 和暂停开关不能进入发布步骤，发布只使用已核验的构建产物。PR 构建不应获得生产秘密；考虑不可信代码和 workflow 修改能影响发布的边界。

用户授权后可配置：合并 main → GitHub Actions 安装锁定依赖 → 构建/检查 → 发布保护检查 → 备份 → OSS 发布 → 线上 GET 验收。事先说明自动发布开启后 main 变更会更新正式站。可用非秘密 flag（如 OSS_DEPLOY_ENABLED=false）暂停部署；名称和默认状态依据项目明确设置，不硬编码所有项目凭据名或默认发布授权。

### 受控手动发布与临时开关

- 若项目已用生产开关阻断部署，首次正式发布或受控补发可在用户明确授权后短时启用开关；优先使用 workflow 的手动触发和显式 `publish` 模式，确认目标为已合并的默认分支提交。开关启用本身不等于发布授权，也不代表已发布。
- 发布前先确认构建/测试通过、OIDC 身份与角色权限正确、覆盖备份成功、生产环境只允许预期分支。OIDC 信任关系应精确约束仓库、分支/环境、audience 与 issuer；角色策略仅授予目标 bucket/prefix 所需动作。Secrets 之外的环境变量可能覆盖仓库级同名值，操作前后都核对实际生效层级。
- 用户授权的单次发布完成后，尽快将临时开关恢复到原先状态；确认保存值确实复位。若用户明确选择持续自动发布，则按已确认的持续状态处理，不擅自复位。不要为“恢复开关”重新触发一轮部署。
- 失败时先停在证据和诊断，不因权限不足扩大信任条件或 OSS 权限，不自动重复有覆盖影响的上传。重试前确认前次运行状态、备份和幂等性；再次启用生产开关属于新的生产操作，须由当前授权覆盖。

云端 build/deploy 不依赖用户 Mac 持续开机；本地可用于配置与提交，不能把本机调度描述为云端运行。锁定远程 commit SHA，等待对应 CI 完成，检查日志且不打印秘密。分别报告 build success、deploy skipped、deploy success；构建成功或 job 绿色但部署被跳过，不能确认网站已更新。记录 PR、commit、Actions run 和实际目标。

## 持续发布身份与运行环境

项目支持时可用 GitHub OIDC 换取短期 STS 凭据，核查信任条件中的仓库、环境、audience 和 issuer，以及角色的实际 OSS 权限。绑定仓库/production 环境不等于只允许所有者发布；结合协作者写权限、主分支保护和环境审批判断实际可发布者。迁移 OIDC 不自动撤销旧 AccessKey 或 Secrets，不擅自改变其他身份权限。

用户明确选择持续自动发布时保留已确认开关状态，后续正常更新不反复要求手动打开 production。排查时同时读取 repository 和 environment 变量，环境同名值可能覆盖仓库值；production 环境、开关与审批是不同控制项。Actions 的运行时与网站构建 Node 版本分别核查，按已验证的官方版本锁定 commit SHA；升级 Action 不要求连带升级网站框架或构建 Node。

## 发布速度与可观测性

耗时诊断、增量发布或并发验收改进时，读取[增量发布与线上校验](release-performance.md)。先从对应 Actions run 分离构建、备份上传和线上校验耗时；可减少未变化文件传输和串行等待，但不能通过删减既定检查、取消备份或扩权提速。

## 云端 SSL 续期

用户选择把 SSL 续期迁到 GitHub Actions 时，读取[云端续期流程](oss-certificate.md#github-actions-云端续期)。续期 workflow 与网站发布独立，分别核验 DNS 验证、证书绑定及私有状态存储权限；记录调度与实际运行证据，不因网站 CI 通过便声称续期可用。

## 发布、备份与验收

覆盖前备份现有对象及必要响应头，明确私有保存位置、保留期限与恢复流程；备份失败停止覆盖。仅上传已检查公开产物，未经授权不删除旧对象，不改 ACL、Policy、DNS 或证书。备份不得放入公开站点目录，回滚应恢复页面、匹配资源及必要 metadata，并重新验收。

必须按[工程与验收](build-verify.md)检查真实入口；选择 OSS 时另读[OSS 流程](oss-certificate.md)。manifest 中 /index.html 对象可读仍可能根 / 不可访问；AccessDenied 不能推出整桶需要公开，也不是修改访问权限的授权。

发布后的线上验收可能比上传耗时更长，尤其是脚本逐域名、逐路由、逐资源读取并比对哈希/字节数，还要核对 404、query 与视频 Range。开始前估算检查规模；运行中区分“上传完成”和“线上验收完成”，等待完整结论，避免仅凭首页打开或 job 尚在执行就宣称整体验收通过。日志在步骤结束前可能不可用或尚无逐项输出；此时依据 Actions job/step 状态耐心等待，并用独立浏览器检查提供补充证据，但不要把浏览器抽查等同于完整 manifest 验收。若耗时明显超出预期，查脚本的超时、重试、串行循环及输出缓冲，识别实际卡点后再优化；不得跳过原定检查来制造成功状态。

## 限定对象撤回

只有在 CMS 撤回或路由退役属于已授权范围时使用。新 build 缺页不代表远端旧对象已删。通过历史 managed manifest 追踪由本流程管理的页面/index 路径；新接管站点先核实基线，不从“远端有而本地无”推定应删除。保留其他资产及不在清单内的对象。

执行链为：完整构建与限定清单 → 备份旧对象/清单及必要 metadata → 上传并核验新版本 → 删除获准退役对象 → 验证缺失/重定向 → 保存新清单。备份、上传或核验失败禁止删除；没有恢复方案不继续。dry-run 只生成本地计划，不联系存储；重复 deploy 和 republish 要能正确恢复条目。删除授权必须来自当前项目范围，技能本身不授予删除权限。

## 交付状态与并发

推送或创建远端提交前重新读取最新目标 ref，对照已审阅基线；有并发改动先保留并重新整合，不能强制覆盖。保护/审批信息无法读取时注明覆盖限制，正常 PR/写入遇到保护要求就遵守，不绕过。

范围仅为 PR 时不合并/部署；已授权正式发布时也不能把草稿 PR 当最终发布。记录对应 SHA 的实际 CI run；仅 main 触发且无 PR run 写“PR CI 未运行”。合并与上传、线上验证分开，他人后续发布注明来源与时间。使用[发布记录](../assets/release-record.md)留证据与回滚步骤。

交付时列明发布状态、线上证据、备份位置与期限、回滚步骤，以及尚未执行或未授权的事项。

## 初次建仓与增量协作

空仓库没有可作为 PR 目标的默认分支。若授权仅限 PR，说明由所有者初始化 README/默认分支后再创建 PR；用户后来明确授权首次写 main 时按新授权执行，不继续重复要求初始化。仓库身份核验通过即可使用现有认证，不索取用户 GitHub Token。

上传源代码、合并 main、开启持续部署和更新正式网站分别记录；源码仓库可能没有部署流程。合并前核对本地未提交内容、用户已删除文章及其他新增页面，解决冲突时保留已确认的两边意图。发布权限覆盖实际新路由和必要备份路径，不因 AccessDenied 改成所有 Bucket 权限。

增量发布只处理本次所需文件；若项目流程要求全站发布则沿用并说明范围。发布队列按站点串行，不取消正在备份或覆盖的任务。用户把验收交给其他人时，完成已授权上传和必要流水线核验后如实交接，不额外扩展视觉验收。
