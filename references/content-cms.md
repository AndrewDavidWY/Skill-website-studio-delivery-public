# 内容结构与 CMS

用于内容密集栏目、搜索/筛选和管理后台；纯展示页面不强加复杂审核系统。先建立真实内容，再判断哪些字段需要编辑。

## 从信息架构到内容覆盖

按受众与任务确定内容支柱、类型、导航归属和关联入口。重复内容采用稳定模板：列表用于发现，详情承载完整内容与行动。记录内容 ID、类型、分类、语言、路由、来源版本、时效、审核责任与公开范围；需翻译时跨语言关联同一内容 ID，避免靠标题猜关联。

栏目按实际范围建立首页、分类/列表、详情及必要的作者、主题、系列关系。用[内容覆盖表](../assets/content-coverage.md)逐条记录全文、图片、引用、关联链接和缺口。未交付正文的条目标“摘要/待补”，不能以卡片数量代表交付完成。重要陈述记录来源，资料冲突明确采用理由。

搜索与筛选针对真实内容索引，记录查询、分类、排序和分页的组合语义。验证无结果、清空/重置、深链接、浏览器前进后退、刷新和手机操作；切换筛选后分页按设计复位，URL 状态和界面一致。卡片指向正确详情，列表、详情和导航没有孤岛或占位成功。

## 编辑能力分层

定义内容模型和编辑边界：哪些字段/页面由 CMS 管理，哪些来自源码或其他系统。不要宣称“全站可编辑”却遗漏导航、页脚、SEO、媒体或语言字段。同步来源文件保留；生成文件应修改其来源和生成流程，避免下次构建覆盖手工改动。

| 能力 | 可验收结果 |
|---|---|
| 编辑 | 真实字段载入、校验和错误提示；无效输入不能冒充成功 |
| 保存 | 源文件或后端真正保存，重新读取/刷新后保留，记录 ID/版本；浏览器临时状态不等于持久化 |
| 预览 | 区分未保存编辑态的实时预览和已持久化草稿预览；各自标明当前记录、语言、版本/状态与实际证据，不把实时预览称为保存成功。说明草稿隔离、有效期和访问边界 |
| 发布 | 仓库交付与线上发布另列；若需构建/缓存刷新，完成后以线上 GET 核对正式版本 |

保存失败保留可恢复状态并准确提示。快速保存按顺序处理或使用等效版本机制，旧回调不得覆盖新成功状态；失败可重试并显示上次成功时间。按风险处理重复提交、并发编辑和过期版本，避免静默覆盖。前后端分别校验权限，匿名者或低权限用户不能靠直调接口保存/发布。角色与审核复杂度按实际需求，不强加多级审批。

## 可见性与状态

按项目必要性分别建模记录草稿/发布/撤回、语言禁用/预览/公开、译文缺失/草稿/复核/当前/过期，以及正文/附件真实语言和业务上的正式发布状态，避免一个布尔值承担所有含义。公开路由、列表计数、推荐、搜索、JSON、metadata 和 sitemap 共享可见性策略；只隐藏正文仍可能泄漏标题、摘要或关键词。

源文变化与译文状态按[多语言参考](multilingual-seo.md)关联。草稿缺项可保存，不应拖垮其他有效公开内容；发布校验须阻断无效产物。生产构建排除私有预览入口及草稿内容，扫描生成 HTML/JSON/JS/XML/text 等实际公开格式。

## 流转与恢复验收

说明保存是否影响线上、谁可预览/发布、静态站何时构建。明确数据源、数据库/媒体存储、备份保留、恢复和导出；源码回滚还需考虑内容/schema 兼容性。演示与生产隔离，验收不对正式内容做未授权写入。

用[编辑验收表](../assets/editor-acceptance.md)记录“编辑 → 保存 → 重读 → 预览 → 发布 → 线上核对”及失败/权限场景。按模型选择撤回→重复同步→撤回期间编辑→重新发布、单语撤回不伤原文、源文更新→译文过期→复核恢复、全草稿空集合等回归；全新构建无页面不等于线上旧对象已撤回，参照[限定对象撤回](github-cloud-delivery.md#限定对象撤回)。未接后端、仅本地存储、部署未触发或缓存未更新分别说明。
