# 增量发布与线上校验

在既有 GitHub Actions → 静态产物 → OSS 流程中使用。先核对当前代码、远端版本和实际运行记录；只优化已授权的流程，保留目标桶、路径白名单、访问设置及验收范围。这里是实施指导，不包含生产脚本、凭据或默认发布授权。

## 先定位耗时

- 从同一 Actions run 提取各步骤起止时间；区分备份上传、产物打包和线上校验，不把整次发布耗时归给某一步。
- 统计对象数量、总字节和大媒体占比，阅读实际请求顺序。逐项建立 TLS 连接、串行 GET、未变化视频反复备份上传都是可验证的瓶颈。
- 分开记录本地和云端测量、无变化发布和真实变更发布。一次测量不保证后续固定耗时；跨区网络和大媒体会改变结果。

## 只处理变化的对象

1. 用经过构建检查的 manifest 作为候选集，先验证目标和路径白名单；dry-run 不读取凭据、不访问 OSS。
2. 对候选对象发 HEAD，比较内容校验值及预期响应头（Content-Type、Cache-Control、Content-Disposition，以及项目实际使用的 Content-Encoding 等）。内容一样但缓存设置不同也要更新。只有确认不存在才能按新文件处理，AccessDenied 或其他错误不能伪装成不存在。
3. 使用 OSS ETag 与本地 MD5 比较前确认上传方式：普通单次上传的 ETag 可用，多段上传、加密等场景不能未经核实把 ETag 当 MD5；不确定时按变化处理或使用经验证的内容元数据校验。跳过判断失败应保守发布或明确失败，不漏传。
4. 只为将被覆盖的变化对象保存旧正文、ETag、必要响应头及私有恢复清单；记录新增对象原先不存在。备份可用 If-Match 锁定检查到的旧版本。全部必要备份成功后才开始任何覆盖。
5. 按资源 → 内页 → 首页的阶段发布，阶段之间设完成屏障，每个上传对象核对远端校验值。资源失败不继续发布页面；不因为并发允许首页提前上线。单站发布任务串行排队，不取消正在覆盖的任务。
6. 记录未变化键、变化键、上传字节、成功对象、备份位置、各阶段耗时及最终状态。无变化时上传字节应为零，但仍执行既定线上检查。失败保留恢复证据，不写成功状态；不自动删除远端旧文件。

同阶段可适度并发；6 路上传/备份是静态站可评估的起点，不是所有项目固定值。按 SDK 的线程安全及连接池能力选择共享客户端或每线程客户端，避免无限并发。检查完整失败路径：未变化跳过、正文变化、响应头变化、新对象、备份失败、上传校验失败，以及阶段顺序。

## 并发线上校验

- 保留已确认的域名与检查集：实际 GET 根路径/query、目录入口和 index 对象、页面版本、缺失文件与目录的自定义 404、资源哈希/长度，以及视频 Range 状态、Content-Range 和片段正文。视频按 Range 取样不等于验收整段视频播放。
- 用有上限的线程池及每线程/每主机持久 HTTPS 连接减少等待；8 路 GET 是可评估起点。保持正常证书和主机名验证，正确读完响应才能复用连接，异常连接关闭后丢弃，配置超时。
- 明确重定向处理；不可把非预期重定向或缓存旧内容当成功。新增路由按项目 manifest/路由来源加入检查，不能只为提速检查首页。
- 输出阶段开始、定期完成计数、总耗时和失败数；失败日志含完整 URL 与原因。记录慢请求和最慢若干项到私有发布报告，并确保 Actions 在失败时也上传报告，避免长时间无输出被误认为卡死。
- 网络/内容异常应使检查失败，不能吞掉异常或跳过剩余检查后宣称完整通过。验证错误状态、正文损坏、Range 错误、连接复用和连接失败处理。

## 上线验证

先完成相关测试和构建/静态检查，再按授权提交、等待对应远端 CI、合并并验证正式发布。核对实际变化/跳过数量、备份上传耗时和线上校验结果；无变化发布只证明跳过分支，不能当作大媒体更新的速度基准。功能、上传、线上 GET 与浏览器验收分别报告，用户交给其他人的验收不擅自接管。
